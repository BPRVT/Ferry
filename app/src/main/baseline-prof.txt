# Baseline profile for Ferry.
#
# WHAT: a list of classes and methods that ART should compile ahead of time (AOT) instead of
# interpreting and JIT-compiling on first use. AGP compiles this into assets/dexopt/baseline.prof,
# and androidx.profileinstaller writes it into the app's ART profile on first run.
#
# WHY IT MATTERS HERE: the primary target is a Fire OS 6 television (API 25) on a modest MStar SoC.
# On API 24-30 there is no Play-supplied cloud profile, so without profileinstaller + this file
# every launch starts fully interpreted and warms up only as the JIT catches on. That is felt twice:
# once at app cold start, and again on the first seconds of a mirroring session, which is exactly
# when the decode pipeline is least able to absorb extra CPU.
#
# FORMAT (human-readable profile, one rule per line):
#   H = hot (called often), S = startup (called during app startup), P = post-startup
#   L<class>;-><method><signature>   for a method,  L<class>;  for a whole class
#
# Class names survive R8 because proguard-rules.pro keeps com.ferry.receiver.** verbatim, so these
# rules still match in a minified release build.
#
# NOTE: this is hand-authored rather than generated. Generating one properly needs the
# androidx.baselineprofile plugin driving a real device or emulator, and neither is available on
# this machine. Hand-authored profiles are a supported input and still help; they are just less
# precise than a recorded run. If a device ever becomes reachable, regenerate this file rather than
# extending it by hand.
